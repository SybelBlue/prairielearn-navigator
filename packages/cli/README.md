# @sybelblue/prairielearn-navigator

Checks a [PrairieLearn](https://www.prairielearn.com) course for problems that
should fail CI, lists and locates what a course contains, adds to it, and
bulk-updates semantic QID references. The diagnostics are
the same ones the
[PrairieLearn Navigator](https://github.com/SybelBlue/prairielearn-navigator)
VS Code extension shows. `check` looks at every course JSON file
(`infoCourse.json`, `infoCourseInstance.json`, `infoAssessment.json`, the
`info.json` of questions, elements, and element extensions, and each
question's `question.html`) under the given
paths (default: `.`). Only errors make it exit non-zero.

```sh
npx -y @sybelblue/prairielearn-navigator check [options] [paths...]
```

| Option | |
| --- | --- |
| `--format pretty\|github` | Output format (default: `pretty`) |
| `--config <path>` | Config file (default: `.pl-navigator.jsonc` in each course root) |
| `--pl-version <version>` | PrairieLearn version to check against (overrides the config) |
| `--schema-cache <dir>` | Where downloaded schemas are cached (overrides the config) |
| `--exclude <glob>` | Skip matching files, relative to the current directory. Repeatable; adds to the config's `excludes`. |
| `--unused-questions <level>` | Severity for questions no assessment uses: `ignored`, `info` (default), `warning`, or `error` (overrides the config) |
| `--unused-tags <level>` | Severity for `infoCourse.json` tags no question uses: `ignored`, `info`, `warning` (default), or `error` (overrides the config) |
| `--unused-assessment-sets <level>` | Severity for `infoCourse.json` assessment sets no assessment uses: `ignored`, `info`, `warning` (default), or `error` (overrides the config) |
| `--missing-question-info <level>` | Severity for directories in `questions/` with files but no `info.json`: `ignored`, `info`, `warning`, or `error` (default) (overrides the config) |

`prairielearn-navigator --version` (or `-v`) prints the installed version.

## Rules

Each diagnostic ends with its rule id, e.g. `[schema]`.

| Rule | Files | Reports |
| --- | --- | --- |
| `json-syntax` | all | JSON syntax errors, including comments and trailing commas, which PrairieLearn's `JSON.parse` rejects |
| `schema` | all | Violations of PrairieLearn's own JSON schema for the selected version. Unknown properties are warnings. |
| `duplicate-question-id` | `infoAssessment.json` | Question ids used more than once (warning) |
| `unused-question` | question `info.json` | Questions no assessment uses, on their `title` (info). Set with `unusedQuestions`. |
| `unused-tag` | `infoCourse.json` | Tags no question lists in its `tags`, on their `name` (warning). Set with `unusedTags`. |
| `unused-assessment-set` | `infoCourse.json` | Assessment sets no assessment names as its `set`, on their `name` (warning). Set with `unusedAssessmentSets`. |
| `undefined-tag` | question `info.json` | Tags in `tags` that `infoCourse.json` does not define and that are not PrairieLearn default tags (`numeric`, `MC`, `code`, …). PrairieLearn creates these in `gray1` (info). |
| `undefined-assessment-set` | `infoAssessment.json` | A `set` that `infoCourse.json` does not define and that is not a PrairieLearn default set (`Homework`, `Quiz`, `Exam`, …). PrairieLearn creates it in `gray1`, with the name as its abbreviation and heading (info). |
| `question-info-missing` | directories in `questions/` | Directories with files but no `info.json` and no question below them, which PrairieLearn fails to load from disk. Shown at the start of the directory's `question.html`, or else its first file. Set with `missingQuestionInfo`. |
| `question-exists` | `infoAssessment.json`, question `info.json` (`template`) | Question ids with no directory, `info.json`, or `question.html` |
| `client-files-course-exist` | question, element, and element extension `info.json` | `clientFilesCourseStyles`/`Scripts` missing from `clientFilesCourse/` |
| `client-files-question-exist` | question `info.json` | `clientFilesQuestionStyles`/`Scripts` missing from `clientFilesQuestion/`; deprecated `clientFiles` (warning) |
| `server-files-course-exist` | question `info.json` | `externalGradingOptions.serverFilesCourse` entries missing from `serverFilesCourse/` |
| `element-files-exist` | element and element extension `info.json` | `controller` and element/extension dependencies missing from the element's directory |
| `<element>-file-exist` | `question.html` | Missing source files of `pl-figure`, `pl-file-download`, `pl-code`, `pl-file-editor`, `pl-graph`, `pl-rich-text-editor`, `pl-excalidraw`, `pl-xss-safe`, and `pl-template`, resolved through each element's `directory` attribute as PrairieLearn does. Invalid `directory` values are errors. |

File rules skip what can't be known before PrairieLearn renders the question:
values containing mustache (`{{`), and `type="dynamic"` files generated by
`server.py`. Files named for student submissions (e.g. `pl-file-editor`'s
`file-name`) are not references.

## Configuration

Put a `.pl-navigator.jsonc` (JSON with comments) next to `infoCourse.json`:

```jsonc
{
  // "latest" (default), a date, or a PrairieLearn commit sha
  "plVersion": "2025-06-01",
  // Relative to this file. Default: $XDG_CACHE_HOME/prairielearn-navigator/schemas
  // or ~/.cache/prairielearn-navigator/schemas
  "schemaCacheDir": ".cache/pl-schemas",
  // Turn rules off or change their severity: "off", "info", "warning", or "error"
  "rules": { "duplicate-question-id": "error" },
  // Exact occurrences suppressed by VS Code's "Ignore this violation" quick fix
  "ignoredDiagnostics": [{
    "file": "questions/draft/info.json",
    "rule": "unused-question",
    "identifier": "draft"
  }],
  // Questions no assessment uses: "ignored", "info" (default), "warning", or "error"
  "unusedQuestions": "warning",
  // Tags and assessment sets no question or assessment uses (default "warning")
  "unusedTags": "info",
  "unusedAssessmentSets": "error",
  // Directories in questions/ with files but no info.json (default "error")
  "missingQuestionInfo": "warning",
  // Files never checked, relative to this file
  "excludes": ["courseInstances/Archive/**", "questions/drafts/**"]
}
```

An ignored diagnostic is matched by its course-relative file and rule. When a
rule has stable semantic context, the quick fix adds an `identifier`, such as a
question id, tag name, or assessment-set name. Other rules fall back to an
exact `message` and 1-based `occurrence` among matching diagnostics in that
file. Existing message/occurrence suppressions remain supported.

PrairieLearn has no numbered releases; it deploys continuously from its
`master` branch. So a version is one of:

- `latest`: today's `master`. Schemas are downloaded at most once a day.
- A date (`YYYY-MM-DD`): `master` as of the end of that day (UTC). The commit is
  looked up once with the GitHub API; set `GITHUB_TOKEN` if you hit its rate
  limit.
- A 40-character commit sha. Fully reproducible, and needs no API call.

Schemas are fetched from GitHub and cached. If they can't be fetched (for
example, offline with an empty cache), schema validation is skipped with a
single warning, and the other rules still run.

Paths can be glob patterns. A glob that matches a directory searches inside
it. Quote globs so the shell passes them through unexpanded:

```sh
npx -y @sybelblue/prairielearn-navigator check "courseInstances/Fa26/**"
```

## GitHub Actions

`--format github` prints workflow annotations, so problems show up inline on
the pull request. Run it from the repository root so annotation paths resolve:

```yaml
- uses: actions/setup-node@v6
  with:
    node-version: 22
- run: npx -y @sybelblue/prairielearn-navigator check --format github
```

Requires Node.js 22 or newer.

## List

The `list` subcommands print a course's QIDs, tags, assessment sets, or
assessments, one per line and sorted.

```sh
npx -y @sybelblue/prairielearn-navigator <noun> list [options]
```

| Command | Line | `--json` element |
| --- | --- | --- |
| `qid list` | `topic/nested` | `{ "qid", "tags" }` |
| `tag list` | `numeric` | `{ "name", "defined", "used" }` |
| `assessment-set list` | `Homework` | `{ "name", "defined", "used" }` |
| `assessment list` | `Fa26/hw1` | `{ "instance", "assessment", "set" }` |

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--json` | Print a JSON array instead of one item per line. `set` is `null` for an assessment without one. |
| `--include-undefined` | `tag list` and `assessment-set list` only: also list names questions or assessments use but `infoCourse.json` does not define |

By default, `tag list` and `assessment-set list` print the names
`infoCourse.json` defines, which are the names `rename` accepts.
`--include-undefined` adds names
that are only used, with `defined: false`. That includes PrairieLearn defaults
a course uses without defining them. Defaults a course doesn't use are never
listed.

Every `info.json` under `questions/` counts as a question, including one nested
inside another question's directory. Files with invalid JSON are read as far
as possible without an error, and `excludes` in `.pl-navigator.jsonc` does not
apply. Use `check` to find invalid files.

## Locate

The `locate` subcommands print where something is defined. They exit non-zero,
with a message on stderr and nothing on stdout, if it isn't.

```sh
npx -y @sybelblue/prairielearn-navigator <noun> locate [options] <target>
```

| Command | Target | Location |
| --- | --- | --- |
| `qid locate` | A QID | The question's `info.json` |
| `assessment locate` | A line of `assessment list` output, e.g. `Fa26/hw1` | The `infoAssessment.json` |
| `tag locate` | A tag | Its `name` in `infoCourse.json`, with spans |
| `assessment-set locate` | An assessment set | Its `name` in `infoCourse.json`, with spans |

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--json` | Print a JSON object instead of a line |

The line is `path:line:column`, or `path` when there is no span. With `--json`:

```json
{
  "path": "infoCourse.json",
  "lineSpan": [7, 7],
  "colSpan": [15, 21]
}
```

`path` is relative to the current directory. `lineSpan` and `colSpan` are
1-based, cover the name's quotes, and are left out for QIDs and assessments.
The end of `colSpan` is exclusive.

A tag or assessment set only counts as defined if `infoCourse.json` defines it.
Names that are only used, including PrairieLearn defaults, are errors, as they
are for `rename`.

## Uses

The `uses` subcommands list every semantic reference to a QID, tag, or
assessment set, one source location per line and sorted by file and position.
Definitions themselves are not uses.

```sh
npx -y @sybelblue/prairielearn-navigator <noun> uses [options] <target>
```

| Command | References |
| --- | --- |
| `qid uses` | Assessment questions, alternatives, and question `template` values |
| `tag uses` | Question `tags` entries |
| `assessment-set uses` | Assessment `set` values |

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--json` | Print a JSON array of locations instead of one location per line |

Text locations are `path:line:column`. With `--json`, each location has the
same shape as `locate`, including the full reference span:

```json
[
  {
    "path": "courseInstances/Fa26/assessments/hw1/infoAssessment.json",
    "lineSpan": [10, 10],
    "colSpan": [17, 23]
  }
]
```

Paths are relative to the current directory. Lines and columns are 1-based,
and span ends are exclusive. A QID can be missing from `questions/`; its
references are still listed so broken courses can be inspected. Tags and
assessment sets must be defined in `infoCourse.json`. A valid target with no
uses succeeds with no text output, or `[]` with `--json`.

## Add

`qid add`, `tag add`, `assessment-set add`, and `assessment add` create a new
question, tag, assessment set, or assessment. Only the name is required: every
other value has a default, and the preview prints what it resolved to. Change
placeholders such as `New Question` before publishing.

```sh
npx -y @sybelblue/prairielearn-navigator <noun> add [options] <name>
```

| Command | Creates | Options |
| --- | --- | --- |
| `qid add <qid>` | `questions/<qid>/info.json` and `question.html` | `--title`, `--topic` |
| `tag add <name>` | An entry in `infoCourse.json`'s `tags` | `--color`, `--description` |
| `assessment-set add <name>` | An entry in `infoCourse.json`'s `assessmentSets` | `--abbreviation`, `--heading`, `--color` |
| `assessment add <instance>/<assessment>` | `infoAssessment.json` in the instance's `assessments/` | `--title`, `--set`, `--number`, `--type` |

All four also take:

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--write` | Apply the planned changes. Without this flag, the command only previews them. |

Defaults come from the course where they can. `--topic` defaults to the
course's first topic, `--set` to its first assessment set, and `--number` to
the next number in that set. A tag or assessment set PrairieLearn already
knows, such as `Homework`, starts from PrairieLearn's definition.

A topic `infoCourse.json` doesn't define prints a warning, and PrairieLearn
creates it. An assessment set must be defined or a PrairieLearn default, so
add a new one first with `assessment-set add`.

```sh
# Preview, then create, a question
npx -y @sybelblue/prairielearn-navigator qid add unit1/quadratic
npx -y @sybelblue/prairielearn-navigator qid add --write \
  --title "Quadratics" --topic Algebra unit1/quadratic

# Add a set, then an exam in it
npx -y @sybelblue/prairielearn-navigator assessment-set add --write Midterm
npx -y @sybelblue/prairielearn-navigator assessment add --write \
  --title "Midterm 1" --set Midterm --type Exam Fa26/midterm1
```

## Rename QIDs

`qid rename` bulk-updates semantic references to one or more question IDs:
assessment question IDs, assessment alternative IDs, and question `template`
values. It does not replace matching prose or comments.

```sh
npx -y @sybelblue/prairielearn-navigator qid rename [options] \
  <old-qid> <new-qid> [<old-qid> <new-qid> ...]
```

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--write` | Apply the planned edits. Without this flag, the command only previews them. |

For example:

```sh
# Preview four QID changes made necessary by a folder reorganization
npx -y @sybelblue/prairielearn-navigator qid rename \
  algebra/add algebra/basics/add \
  algebra/subtract algebra/basics/subtract

# Apply the same reference edits
npx -y @sybelblue/prairielearn-navigator qid rename --write \
  algebra/add algebra/basics/add \
  algebra/subtract algebra/basics/subtract
```

The command changes references only. Move the question directories separately;
the command can run before or after that move and does not require either QID's
directory to exist. Automatic move detection is available only for moves made
through the PrairieLearn Navigator VS Code extension.

## Rename tags

`tag rename` renames a tag defined in `infoCourse.json`: its definition, every
question's `tags` entry, and `ignoredDiagnostics` entries in
`.pl-navigator.jsonc` that name it. A question that already lists the new name
drops the old one instead of listing the tag twice.

```sh
npx -y @sybelblue/prairielearn-navigator tag rename [options] <old-tag> <new-tag>
```

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--write` | Apply the planned edits. Without this flag, the command only previews them. |

The old tag must be defined in `infoCourse.json`, and the new name must not
be. In VS Code, Rename Symbol (F2) on the tag does the same.

## Rename assessment sets

`assessment-set rename` renames an assessment set defined in
`infoCourse.json`: its definition, every assessment's `set`, and
`ignoredDiagnostics` entries in `.pl-navigator.jsonc` that name it. The set's
`abbreviation` and `heading` are left as they are.

```sh
npx -y @sybelblue/prairielearn-navigator assessment-set rename [options] <old-set> <new-set>
```

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--write` | Apply the planned edits. Without this flag, the command only previews them. |

Quote names with spaces, e.g. `assessment-set rename "Quiz" "Practice Quiz"`.
The old set must be defined in `infoCourse.json`, and the new name must not
be. In VS Code, Rename Symbol (F2) on the set does the same.

## Rename assessments

`assessment rename` renames an assessment within its course instance: it moves
the assessment's directory, removes directories that leaves empty, and updates
`ignoredDiagnostics` entries in `.pl-navigator.jsonc` for files in it. Nothing
else in a course names an assessment's directory. The assessment's `uuid` and `title` are left as they
are.

```sh
npx -y @sybelblue/prairielearn-navigator assessment rename [options] <old-assessment> <new-assessment>
```

| Option | |
| --- | --- |
| `--course <path>` | Course directory or a path inside one (default: `.`) |
| `--write` | Move the directory and apply the planned edits. Without this flag, the command only previews them. |

Both names are as `assessment list` prints them, e.g.
`assessment rename Fa26/hw1 Fa26/unit1/hw1`. The new name must be in the same
course instance, must not exist yet, and must not be inside another assessment.
`excludes` globs are not updated, because a glob can't be rewritten reliably.
A directory that still holds anything, even a hidden file like `.DS_Store`, is
kept.

## Deprecated commands

`rename-qids`, `rename-tags`, and `rename-assessment-sets` still run
`qid rename`, `tag rename`, and `assessment-set rename`, with a warning on
stderr. They will be removed in 1.4.0.

## Library API

The package is also an ES module library (Node 22+, typed, no runtime
dependencies). It gives tools the same course logic as the CLI and the VS Code
extension, without starting either.

### Course files

| Export | Returns |
| --- | --- |
| `findCourseRoot(filePath: string, cache?: Map<string, string \| null>): string \| null` | The nearest directory at or above `filePath`'s directory that contains `infoCourse.json`, or `null`. To search from a directory `dir`, pass `path.join(dir, "infoCourse.json")`; the file need not exist. Reuse `cache` across calls to look each directory up once. |
| `parseJsonDoc(text: string): JsonDoc` | The document parsed as JSON with comments and trailing commas, with its `value` (undefined if the text has no root value) and syntax `errors`, each with an `offset`, `length` and `message`. Its `tree` is opaque: pass the `JsonDoc` to `courseTags`. |
| `strictJsonErrors(text: string): JsonDoc["errors"]` | Syntax errors under strict JSON, as PrairieLearn reads course files: comments and trailing commas are errors. |
| `assessmentQuestionRefs(text: string): AssessmentQuestionRef[]` | Every `zones[*].questions[*].id` (`kind: "question"`) and `zones[*].questions[*].alternatives[*].id` (`kind: "alternative"`) in an `infoAssessment.json`, in document order, duplicates included. `startOffset` and `endOffset` exclude the quotes. Comments are allowed. On other syntax errors it returns the ids it can recover and does not throw. It reads the same references as the `question-exists` rule and `qid rename`, and needs no course root or file system. |

### Tags and colors

| Export | Value |
| --- | --- |
| `courseTags(doc: JsonDoc): CourseTag[]` | The tags an `infoCourse.json` defines, in order. Each has its `name`, `color` and `description` (`TagInfo`), its `index` in `tags`, and the offsets of its name string, quotes included (`nameStart`, `nameEnd`). |
| `plDefaultTag(name: string): TagInfo \| undefined` | The tag PrairieLearn defines itself under `name`, if there is one. |
| `plDefaultTagList(): readonly TagInfo[]` | Every PrairieLearn default tag, in PrairieLearn's order. |
| `plBadgeColors: Readonly<Record<string, Readonly<{ text: string; background: string }>>>` | PrairieLearn's badge colors (`red1` … `gray3`) as CSS hex colors. Frozen. |
| `implicitTagColor: string` | The color PrairieLearn gives a tag `infoCourse.json` doesn't define (`"gray1"`). |

```ts
import * as fs from "node:fs";
import * as path from "node:path";
import {
  assessmentQuestionRefs,
  courseTags,
  findCourseRoot,
  implicitTagColor,
  parseJsonDoc,
  plBadgeColors,
  plDefaultTag,
  strictJsonErrors,
} from "@sybelblue/prairielearn-navigator";

const assessment = "/path/to/course/courseInstances/Fa26/assessments/hw1/infoAssessment.json";
const root = findCourseRoot(assessment);
if (root) {
  const infoCourse = fs.readFileSync(path.join(root, "infoCourse.json"), "utf8");
  const defined = new Map(courseTags(parseJsonDoc(infoCourse)).map((tag) => [tag.name, tag]));
  const tag = defined.get("numeric") ?? plDefaultTag("numeric");
  const badge = plBadgeColors[tag?.color ?? implicitTagColor]; // { text, background }
}

const text = fs.readFileSync(assessment, "utf8");
for (const { id, kind, startOffset } of assessmentQuestionRefs(text)) {
  console.log(kind, id, "at", startOffset);
}
const syntaxErrors = strictJsonErrors(text); // what PrairieLearn would reject
```

### Question files

`createQuestionFileResolver` is a typed, headless resolver for tools that need
the files each question uses:

```ts
import { createQuestionFileResolver } from "@sybelblue/prairielearn-navigator";

const resolver = createQuestionFileResolver({
  courseRoot: "/path/to/course",
  questions: [
    { qid: "vectors/addition", directory: "questions/vectors/addition" },
  ],
});

const initial = await resolver.resolveAll();
const changed = await resolver.update(["clientFilesCourse/plots.js"]);
```

`resolveAll()` returns a `Map` from QID to a `QuestionFileResolution` with
course-relative file paths, `question-local`, `template-local`, or
`course-level` provenance, and diagnostics for dependencies that cannot be
resolved statically. `update()` maintains the dependency graph and returns
only questions affected by the supplied course-relative paths. The resolver
does not watch the filesystem; callers decide how and when to batch changes.
